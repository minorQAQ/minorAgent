# HTML 输出质检清单（QA Checklist）

本文档是 HTML 演示文稿输出的全面质量检查清单。Agent 在交付前必须逐项核验。

---

## 零、流程合规检查（4 项）— ⛔ 先于所有技术检查

| # | 检查项 | 标准 | 通过 |
|---|--------|------|------|
| 1 | 阶段 a human_interaction | 已调用 `human_interaction(selection)` 完成方向锚定（风格/受众/场合/画布/页数/叙事风格），用户已选择 | ☐ |
| 2 | 阶段 b human_interaction | 已调用 `human_interaction(approval)` 完成设计锁定（色板 hex + 字体 + 页面节奏），用户已审批 | ☐ |
| 3 | 阶段 c human_interaction | 已调用 `human_interaction(approval)` 完成内容大纲审批（逐页标题+要点+配图策略+图表），用户已审批 | ☐ |
| 4 | 无跳过/合并 | 三个阶段各自独立完成，未合并、未跳过、未用纯文本或 `tool_call(confirm)` 替代 `human_interaction` | ☐ |

> **以上 4 项中任何一项未通过，不得进入技术检查阶段，必须回到对应阶段重新与用户对齐。**

---

## 一、结构检查（8 项）

| # | 检查项 | 标准 | 通过 |
|---|--------|------|------|
| 1 | 根容器尺寸 | 根 `div` 或 `body` 内主容器精确为 `width: 1280px; height: 720px` | ☐ |
| 2 | 溢出控制 | 根容器设置 `overflow: hidden`，无内容溢出可视区域 | ☐ |
| 3 | 定位方式 | 禁止使用 `position: fixed` 和 `position: sticky`，仅允许 `relative` / `absolute` / `static` | ☐ |
| 4 | 标签闭合 | 所有 HTML 标签正确闭合，无未闭合标签 | ☐ |
| 5 | 脚本限制 | 除动画引擎外，无其他 `<script>` 标签，无事件绑定 | ☐ |
| 6 | 嵌入媒体限制 | 不使用 `<iframe>`、`<video>`、`<audio>` 标签 | ☐ |
| 7 | 特殊字符转义 | 内容中的 `&` 已转义为 `&amp;` | ☐ |
| 8 | 嵌套层级 | HTML 元素最大嵌套深度不超过 4 层 | ☐ |

---

## 二、样式检查（8 项）

| # | 检查项 | 标准 | 通过 |
|---|--------|------|------|
| 1 | 颜色调色板 | 所有颜色值来源于 `spec_lock.md` 中定义的调色板，无额外/内联颜色（透明除外） | ☐ |
| 2 | CSS 变量定义 | 所有颜色变量在 `:root` 中统一定义，变量名与 spec_lock 一致 | ☐ |
| 3 | 字体引用 | 不引用任何外部字体（无 `@import url()` 字体、无 Google Fonts 等） | ☐ |
| 4 | 字体栈 | 使用系统安全字体栈（如 `'Segoe UI', 'PingFang SC', 'Microsoft YaHei', sans-serif`） | ☐ |
| 5 | 禁止 CSS 动画 | 不使用 `@keyframes`、`animation` 属性（动画仅由 JS 引擎驱动） | ☐ |
| 6 | 样式位置 | 所有样式写在 `<style>` 块中或使用内联 `style` 属性，无外部样式表 | ☐ |
| 7 | 卡片一致性 | 卡片统一使用相同的 `border-radius`、`box-shadow`、`padding` 值 | ☐ |
| 8 | 排版层级 | 标题/副标题/正文/注释的字体大小、字重、颜色层级与 spec_lock 一致 | ☐ |

---

## 三、动画检查（5 项）

| # | 检查项 | 标准 | 通过 |
|---|--------|------|------|
| 1 | 动画引擎完整性 | 动画引擎 `<script>` 存在且为页面内**唯一**脚本 | ☐ |
| 2 | 动画数量限制 | 锚点页（封面/封底/分隔页）≤2 个动画；信息密集页 ≤6 个动画；呼吸动画 ≤1 个 | ☐ |
| 3 | data-anim 属性 | 所有 `data-anim` 属性拼写正确（`fade-up` / `scale-in` / `slide-left` / `slide-right` / `zoom-in`），无自定义动画名 | ☐ |
| 4 | 无 CSS 动画冲突 | CSS 中无 `transition` 属性对动画元素干扰，无 `animation-delay` 等可产生冲突的属性 | ☐ |
| 5 | 交错延迟合理 | `data-anim-delay` 取值在 0~2 秒范围内，`data-anim-stagger` 容器内子元素间隔合理 | ☐ |

---

## 四、内容检查（5 项）

| # | 检查项 | 标准 | 通过 |
|---|--------|------|------|
| 1 | 标题一致性 | 页面标题/主标题与 `spec_lock.md` 中定义的内容大纲一致 | ☐ |
| 2 | 要点完整性 | `spec_lock.md` 中列出的关键要点均已呈现在页面中 | ☐ |
| 3 | 数据真实性 | 无伪造数据、图表数值、统计数据、引用来源——如 spec_lock 未提供具体数据，使用占位标记而非虚构 | ☐ |
| 4 | 图片路径 | `<img>` 标签的 `src` 路径指向同目录下的实际图片文件，路径使用相对路径 | ☐ |
| 5 | 内容不溢出 | 在 1280×720 画布内所有内容完全可见，无截断或越过边界的内容 | ☐ |

---

## 五、文件命名与交付

| # | 检查项 | 标准 | 通过 |
|---|--------|------|------|
| 1 | 目录结构 | 所有 HTML 文件位于 `workspace/ppt_{topic}/` 目录下 | ☐ |
| 2 | 文件命名 | 页面文件按顺序命名为 `1.html`、`2.html`、...，每个为自包含的完整 HTML 文档 | ☐ |
| 3 | 可独立打开 | 每个 `{N}.html` 可在浏览器中直接打开，画布尺寸正确，动效正常 | ☐ |
| 4 | 图片本地化 | 所有引用的图片文件存放在与 HTML 同目录下 | ☐ |
| 5 | Base64 转换 | 最终交付前必须运行 `python {SKILL_DIR}/attachments/complete_htmls_to_base64.py {workspace_dir}` 将所有图片转为内嵌 base64 | ☐ |

---

## 质检流程

1. **Agent 自检**：生成每页 HTML 后，逐项核对上述清单
2. **独立打开验证**：在浏览器中打开每个 `{N}.html` 验证视觉效果
3. **自动化检查**：运行 `python {SKILL_DIR}/attachments/complete_htmls_to_base64.py {workspace_dir}` 确保图片路径全部可解析
4. **通过标准**：所有检查项均为 ☑ 方可交付
